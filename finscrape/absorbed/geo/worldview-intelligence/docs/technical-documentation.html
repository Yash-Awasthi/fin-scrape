Technical Documentation for Developers

📍 Project Overview

WorldView Intelligence is a real-time global intelligence dashboard that combines a 3D CesiumJS globe with live OSINT (Open Source Intelligence) data feeds. It tracks aircraft, satellites, ships, earthquakes, conflict zones, missile launches, news, traffic, and weather — all rendered on an interactive globe with military-inspired visual modes.

Real-Time Data

WebSocket-driven live updates from multiple OSINT sources including OpenSky, USGS, CelesTrak, and RSS news feeds.

3D Visualization

CesiumJS-powered interactive globe with satellite imagery, terrain, and custom entity rendering for each data layer.

9 Data Layers

Aircraft, Satellites, Ships, Earthquakes, Conflicts, Missiles, News, Traffic, and Weather — each with dedicated rendering.

AI Intelligence

Anomaly detection, situation reports, and escalation prediction with rule-based logic (OpenAI integration prepared).

🏗 Architecture

The application follows a client-server architecture with real-time data streaming. The backend fetches and caches data from external APIs, then pushes updates to connected frontends via WebSocket.

External APIs (OpenSky, USGS, CelesTrak, Open-Meteo, GDELT, RSS) | v Backend Services (aircraft.ts, satellites.ts, earthquakes.ts, ...) | +----> Redis / In-Memory Cache (TTL per layer) | +----> REST API (/api/layers/*) <--- Frontend fetch (fallback) | \----> WebSocket Server (scheduled loops per layer) | v Broadcast layer_update to subscribed clients | v Frontend websocket.ts → appStore.setLayerData() | v GlobeView subscribes to store → update*Layer() → Cesium entities
Key Insight The primary data path uses WebSocket push. The REST API serves as a fallback and is used for search, intelligence reports, and initial data loads.

Step-by-Step Setup

1

Clone the repository

git clone <repository-url>
cd "WorldView Intelligence"
2

Install Backend Dependencies

cd backend
cp .env.example .env
npm install
3

Install Frontend Dependencies

cd ../frontend
cp .env.example .env
npm install
4

Configure the Cesium Token

Open frontend/.env and add your Cesium Ion token:

VITE_CESIUM_ION_TOKEN=your_cesium_ion_token_here
5

Start Redis (Optional)

The app works without Redis using an in-memory fallback, but for production-like behavior:

docker compose up redis -d
6

Start the Backend

cd backend
npm run dev

Backend starts on http://localhost:3001 (HTTP) and ws://localhost:3002 (WebSocket).

7

Start the Frontend (in a new terminal)

cd frontend
npm run dev

Frontend starts on http://localhost:5173. The Vite dev server proxies /api requests to the backend.

You're up and running! Open http://localhost:5173 in your browser. You should see the landing page with a theme selector. Click "Enter Command Center" to access the globe.

How the Backend Starts

The entry point backend/src/index.ts does the following in order:

  1. Loads environment variables from .env via dotenv
  2. Creates an Express app with CORS, JSON parsing, rate limiting, and API routes
  3. Starts the HTTP server on port 3001
  4. Starts the WebSocket server on port 3002
  5. Registers graceful shutdown handlers for SIGINT and SIGTERM

📡 WebSocket Protocol

The WebSocket server runs on port 3002 and provides real-time data streaming with per-layer subscriptions.

Connecting

// Connect to the WebSocket server
const ws = new WebSocket('ws://localhost:3002');

Subscribing to Layers

After connecting, send a subscribe message for each layer you want updates on:

// Subscribe to a layer
ws.send(JSON.stringify({
  "action": "subscribe",
  "layer": "aircraft"
}));

// Available layers:
// aircraft, satellites, ships, earthquakes, conflicts,
// missiles, news, traffic, weather

Receiving Updates

The server broadcasts updates at configured intervals. Each message looks like:

{
  "type": "layer_update",
  "layer": "aircraft",
  "data": [ ... ],
  "timestamp": 1710000000000
}

🔌 Data Services

Each data layer has a dedicated service file in backend/src/services/. Every service follows the same pattern:

  1. Check cache — Look for cached data in Redis (or in-memory fallback)
  2. Fetch from source — If cache miss or expired, call the external API or generate simulated data
  3. Transform data — Normalize the response into the app's type schema
  4. Cache result — Store in cache with a TTL appropriate for that layer
  5. Return data — Return the normalized array to the caller

Real API Integrations

Aircraft — OpenSky Network

Fetches live ADS-B aircraft positions. Supports optional authentication for higher rate limits. Returns callsign, position, velocity, heading, altitude, origin country, and aircraft category (commercial, military, cargo).

API: https://opensky-network.org/api/states/all

Satellites — CelesTrak TLE

Downloads Two-Line Element (TLE) sets from CelesTrak and propagates orbital positions using satellite.js. TLE data is refreshed hourly; position propagation runs every 30 seconds.

API: https://celestrak.org/NORAD/elements/gp.php

Earthquakes — USGS

Fetches GeoJSON earthquake data from the US Geological Survey. Includes magnitude, depth, location, and tsunami warnings.

API: https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_hour.geojson

Weather — Open-Meteo

Fetches weather conditions from the free Open-Meteo API. Returns temperature, wind speed, humidity, and weather condition.

API: https://api.open-meteo.com/v1/forecast

News — RSS Feeds

Aggregates RSS feeds from BBC, Reuters, Al Jazeera, The Guardian, and Sky News. News items are geocoded onto the map based on content analysis.

Simulated Data

The following layers use algorithmically generated data that mimics real-world patterns:

  • Ships — Positions along major international shipping routes with realistic vessel types, flags, and speeds
  • Conflicts — Events in known conflict zones (Ukraine, Gaza, Syria, Sudan, Red Sea, Myanmar) with data structure matching ACLED format
  • Missiles — Launch sites, parabolic trajectory arcs, and predicted impact zones
  • Traffic — Congestion levels for major world cities (New York, London, Dubai, Tokyo, Paris, Singapore)

💾 Caching Layer

The caching system (backend/src/utils/cache.ts) provides a unified interface with automatic fallback:

  1. Primary: Redis — Connects via ioredis to the Redis instance specified in REDIS_URL
  2. Fallback: In-Memory Map — If Redis is unavailable, uses a JavaScript Map with manual TTL expiry

Each layer has its own cache key and TTL, matching its update interval.

For Development You don't need Redis running locally. The app automatically falls back to in-memory caching with a console warning.

➕ Guide: Adding a New Data Layer

Follow these steps to add a new data layer (e.g., "Volcanoes"):

1

Define Types

Add the new entity type in both backend/src/types/index.ts and frontend/src/types/index.ts:

export interface Volcano {
  id: string;
  name: string;
  position: { lat: number; lng: number };
  status: 'active' | 'dormant' | 'erupting';
  elevation: number;
}

// Add to the LayerData interface:
export interface LayerData {
  // ... existing layers ...
  volcanoes: Volcano[];
}
2

Create Backend Service

Create backend/src/services/volcanoes.ts following the existing service pattern:

import { cache } from '../utils/cache';

export async function fetchVolcanoes(): Promise<Volcano[]> {
  const cached = await cache.get('volcanoes');
  if (cached) return JSON.parse(cached);

  // Fetch from API or generate data
  const data = await fetchFromSource();

  await cache.set('volcanoes', JSON.stringify(data), 300);
  return data;
}
3

Add REST Route

Add to backend/src/routes/api.ts:

router.get('/layers/volcanoes', asyncHandler(async (_req, res) => {
  const data = await fetchVolcanoes();
  res.json({ layer: 'volcanoes', data, timestamp: Date.now() });
}));
4

Add WebSocket Subscription

In backend/src/websocket/server.ts, add the new layer to the subscription handler and create a scheduled fetch loop with the desired interval.

5

Create Frontend Layer Renderer

Create frontend/src/layers/volcanoLayer.ts to render Cesium entities for each volcano.

6

Update Frontend State & UI

  • Add volcanoes: [] to the store's initial layers state
  • Add the layer config in App.tsx's LAYER_CFG array
  • Call the renderer from GlobeView.tsx

🔗 Guide: Adding an API Integration

To integrate a new external data source:

  1. Add env vars — Add any API keys to backend/.env.example and backend/.env
  2. Create the fetch function — In the relevant service file, use axios to call the API
  3. Handle errors gracefully — Always wrap API calls in try/catch and fall back to cached or simulated data
  4. Respect rate limits — Cache aggressively; most free APIs have strict rate limits
  5. Type the response — Use Zod schemas or TypeScript interfaces to validate API responses
import axios from 'axios';
import { cache } from '../utils/cache';

export async function fetchFromExternalAPI() {
  const cached = await cache.get('my-api-data');
  if (cached) return JSON.parse(cached);

  try {
    const { data } = await axios.get('https://api.example.com/data', {
      headers: { 'Authorization': `Bearer ${process.env.MY_API_KEY}` },
      timeout: 10000,
    });
    const normalized = transformData(data);
    await cache.set('my-api-data', JSON.stringify(normalized), 120);
    return normalized;
  } catch (err) {
    console.error('[MyAPI] Fetch failed:', err);
    return generateFallbackData();
  }
}
