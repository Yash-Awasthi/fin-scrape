Complete Setup Guide — From Zero to Running & Debugging
This guide assumes you have never set up a Node.js project before. Every single step is explained.

i What You'll Set Up

By the end of this guide, you will have:

  • ✓ Node.js, Git, and a code editor installed
  • ✓ The WorldView Intelligence source code on your machine
  • ✓ All required API keys created and configured
  • ✓ The backend running on http://localhost:3001
  • ✓ The WebSocket server running on ws://localhost:3002
  • ✓ The frontend running on http://localhost:5173
  • ✓ Debugging configured in your editor
  • ✓ Live data streaming to a 3D globe in your browser
Time Estimate First-time setup takes about 15–25 minutes. If you already have Node.js and Git installed, it takes about 5 minutes.

1 Install Node.js

Node.js is the JavaScript runtime that runs the backend server and provides npm (the package manager) for installing libraries.

Windows

  1. Go to https://nodejs.org
  2. Click the "LTS" download button (the green one — currently v20.x or higher)
  3. Run the downloaded .msi installer
  4. Click Next through all steps, keeping all default options checked
  5. When you see "Automatically install the necessary tools" — check that box
  6. Click Install, then Finish

macOS

  1. Go to https://nodejs.org
  2. Download the macOS Installer (.pkg) for the LTS version
  3. Double-click the .pkg file and follow the installer
  4. Alternative: If you have Homebrew, run: brew install node

Verify Installation

Open a new terminal (PowerShell on Windows, Terminal on macOS) and run:

node --version
# Should output: v20.x.x or higher

npm --version
# Should output: 10.x.x or higher
Must open a NEW terminal! If you had a terminal open before installing Node.js, it won't recognize the node command. Close it and open a fresh one.

2 Install Git

Git is the version control tool used to clone (download) the project code.

Windows

  1. Go to https://git-scm.com/download/win
  2. The download starts automatically — run the installer
  3. Click Next through all screens, accepting all defaults
  4. On the "Choosing the default editor" screen, you can pick Visual Studio Code if you prefer
  5. Click Install, then Finish

macOS

  1. Open Terminal and type git --version
  2. If Git is not installed, macOS will prompt you to install the Xcode Command Line Tools — click Install
  3. Alternative: brew install git

Verify Installation

git --version
# Should output: git version 2.x.x

You need a code editor to browse and edit the source code. We recommend VS Code or Cursor.

VS Code

  1. Go to https://code.visualstudio.com
  2. Click Download for your operating system
  3. Run the installer with default settings
  4. Check "Add to PATH" if prompted (Windows)

Cursor (AI-powered VS Code fork)

  1. Go to https://cursor.sh

4 Install Docker Desktop (Optional)

Docker is optional. The app works fully without it using an in-memory cache. Docker is only needed if you want:

  • Redis caching (performance improvement, not required)
  • PostgreSQL database (provisioned but not yet used by the app)
  • Full-stack containerized deployment

Windows / macOS

  1. Go to https://www.docker.com/products/docker-desktop
  2. Click Download Docker Desktop
  3. Run the installer (Windows may require WSL 2 — the installer will guide you)
  4. After installation, launch Docker Desktop and wait for it to say "Docker is running"

Verify Installation

docker --version
# Should output: Docker version 24.x.x or higher

docker compose version
# Should output: Docker Compose version v2.x.x

7 Create a Cesium Ion Token REQUIRED

The Cesium Ion token is the only required API key. Without it, the 3D globe will not display satellite imagery or terrain. It is 100% free.

Step-by-Step: Create Your Cesium Ion Token

  1. Go to https://ion.cesium.com/signup
  2. Click "Sign up" — you can sign up with GitHub, Google, or email
  3. Fill in the registration form and verify your email if required
  4. Once logged in, you will land on the Cesium Ion dashboard
  5. In the left sidebar, click "Access Tokens"
  6. You will see a "Default Token" already created — you can use this one
  7. Click the clipboard icon next to the token to copy it
  8. Save this token — you will paste it into the frontend/.env file in Step 13
How to create a custom token (optional) Click "Create Token" button, name it WorldView Intelligence, keep all default asset permissions checked, and click Create. Copy the generated token.

Your token will look something like this (a long string of random characters):

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJqdGkiOiI4NTQ2YzRiNy01Y...

8 Create OpenSky Network Account OPTIONAL FREE

OpenSky provides live aircraft tracking data. The app works without an account (anonymous access), but with credentials you get higher rate limits and more data.

Step-by-Step

  1. Go to https://opensky-network.org
  2. Click "Register" in the top navigation
  3. Fill in: Username, Email, Password
  4. Complete the CAPTCHA and click Register
  5. Check your email and click the verification link
  6. Note down your username and password — these go into backend/.env

You will use these values later:

OPENSKY_USERNAME=your_username_here
OPENSKY_PASSWORD=your_password_here

9 Create TomTom API Key OPTIONAL FREE TIER

TomTom provides real traffic data. Without it, the app uses simulated traffic data for major cities.

Step-by-Step

  1. Go to https://developer.tomtom.com
  2. Click "Register" and create an account (email + password)
  3. Verify your email address
  4. Once logged in, go to "Dashboard"
  5. You should see a default application with an API Key
  6. If not, click "Add a new key" → name it WorldView → select "Traffic" product
  7. Copy the API Key

Your key will look like: A1b2C3d4E5f6G7h8I9j0K1l2M3n4O5p6

TOMTOM_API_KEY=your_api_key_here
Free Tier TomTom's free tier includes 2,500 free requests per day, which is more than enough for development.

10 Create N2YO API Key OPTIONAL FREE

N2YO provides additional satellite tracking data beyond what CelesTrak offers. The app already uses CelesTrak (no key needed), so this is purely supplemental.

Step-by-Step

  1. Go to https://www.n2yo.com/api/
  2. Scroll down to "Get Your API Key"
  3. Enter your email address and click "Generate Key"
  4. Check your email — the API key will be sent to you
  5. Copy the key from the email
N2YO_API_KEY=your_api_key_here

11 Create NewsAPI Key OPTIONAL FREE

NewsAPI provides additional news sources beyond the built-in RSS feeds. The app already works with free RSS feeds (BBC, Reuters, etc.) without this key.

Step-by-Step

  1. Go to https://newsapi.org/register
  2. Fill in: Name, Email, Password
  3. For "What are you building?", select "I'm a developer"
  4. Click "Submit"
  5. Your API key is displayed immediately on the next page
  6. It's also sent to your email
NEWS_API_KEY=your_api_key_here
Free Tier Limitation NewsAPI's free plan only allows requests from localhost. In production, you would need a paid plan or use the built-in RSS feeds.

12 Create OpenAI API Key OPTIONAL

OpenAI powers enhanced AI situation reports. Without it, the app uses rule-based intelligence analysis (which still works well). The OpenAI integration is prepared but not yet fully wired in the current codebase.

  7. Click "Create secret key"

OPENAI_API_KEY=sk-proj-abc123xyz...

13 Configure Environment Files

Environment files (.env) contain your API keys and configuration. You need to create two of them — one for the backend, one for the frontend.

13a. Create the Backend .env File

In your terminal, from the project root:

# Navigate to the backend folder
cd backend

# Copy the example file to create your .env
cp .env.example .env

On Windows PowerShell, use:

Copy-Item .env.example .env

Now open backend/.env in your editor and fill in your values:

backend/.env
# Server ports (keep these as-is unless you have a conflict) PORT=3001 WS_PORT=3002 # PostgreSQL — keep default, not used yet DATABASE_URL=postgresql://postgres:password@localhost:5432/worldview # Redis — keep default, app falls back to in-memory if unavailable REDIS_URL=redis://localhost:6379 # ──── API KEYS ──────────────────────────────────────────── # Paste your keys below. Delete "your_..._here" and paste. # Leave blank if you don't have one — the app still works. # OpenSky (from Step 8) OPENSKY_USERNAME= OPENSKY_PASSWORD= # TomTom (from Step 9) TOMTOM_API_KEY= # ADS-B Exchange (not used in current code, leave blank) ADSB_EXCHANGE_API_KEY= # N2YO (from Step 10) N2YO_API_KEY= # GDELT (no key needed, leave blank) GDELT_API_KEY= # NewsAPI (from Step 11) NEWS_API_KEY= # OpenAI (from Step 12) OPENAI_API_KEY= # Cesium (not used by backend currently, leave blank) CESIUM_ION_TOKEN=

13b. Create the Frontend .env File

# Navigate to the frontend folder
cd ../frontend

# Copy the example file
cp .env.example .env

On Windows PowerShell:

Copy-Item .env.example .env

Open frontend/.env and paste your Cesium Ion token:

frontend/.env
# REQUIRED — Paste your Cesium Ion token from Step 7 VITE_CESIUM_ION_TOKEN=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJqdGkiOiI4NTQ2... # These are correct for local development — don't change VITE_API_BASE_URL=http://localhost:3001 VITE_WS_URL=ws://localhost:3002
CRITICAL: Replace the Cesium token! You must replace your_cesium_ion_token_here with your actual token from Step 7. The globe will not render imagery without a valid token.
Never commit .env files to Git! The .env files contain your private API keys. They should already be in .gitignore. Never share them or push them to a public repository.

14 Install Dependencies

Now you need to install all the JavaScript libraries the project depends on. You need to do this separately for the backend and frontend.

14a. Install Backend Dependencies

# Make sure you're in the project root
cd "C:\Users\YourName\source\repos\WorldView Intelligence"

# Go to the backend folder and install
cd backend
npm install

This will:

  • Read package.json to find all required packages
  • Download them into a node_modules/ folder
  • Create a package-lock.json file (locks exact versions)
  • Takes about 30–60 seconds

14b. Install Frontend Dependencies

# Go to the frontend folder and install
cd ../frontend
npm install

This takes a bit longer (1–2 minutes) because CesiumJS is a large library.

Success Check Both commands should finish without errors. You may see some WARN messages — those are fine. Only red ERR! messages indicate a problem.
If npm install fails
  1. Make sure Node.js v20+ is installed: node --version
  2. Try deleting node_modules and package-lock.json, then re-run npm install
  3. On Windows, try running the terminal as Administrator
  4. Check your internet connection — npm needs to download packages

15 Start the Backend Server

Open a terminal (or use the integrated terminal in VS Code / Cursor) and run:

# From the project root
cd backend
npm run dev

What npm run dev does:

  • Runs tsx watch src/index.ts — this compiles and runs the TypeScript code
  • The watch flag means it auto-restarts when you edit any file
  • Starts the HTTP server on port 3001
  • Starts the WebSocket server on port 3002

Expected Output

[Server] HTTP server running on port 3001
[Server] API available at http://localhost:3001/api
[Server] WebSocket server running on port 3002

If you see Redis connection warnings like [Cache] Redis unavailable, using in-memory cache, that's normal — the app works without Redis.

Keep this terminal open! The backend needs to keep running. Open a second terminal for the frontend in the next step.

Quick Test

Open your browser and go to: http://localhost:3001/api/health

You should see a JSON response like:

{
  "status": "ok",
  "uptime": 5.123,
  "timestamp": 1710000000000,
  "memory": { ... }
}

17 Verify Everything Works

1

Open the app

Go to http://localhost:5173 in Chrome, Edge, or Firefox.

2

See the landing page

You should see the WorldView Intelligence landing page with a theme selector (Command, Cyber, or Nexus). Pick any theme and click "Enter Command Center".

3

Verify the 3D globe

Check data layers

Congratulations! If you can see the globe with data layers, the WebSocket is connected, and the API returns data — your setup is complete! You can now start developing.

18 Debugging in VS Code / Cursor

To debug the code with breakpoints (pause execution and inspect variables), set up launch configurations:

18a. Debug the Backend (Node.js)

Setup

  1. In VS Code / Cursor, press Ctrl+Shift+D (Windows) or Cmd+Shift+D (Mac) to open the Run and Debug panel
  2. Click "create a launch.json file"
  3. Select "Node.js" from the dropdown
  4. Replace the generated content with the configuration below

Create or edit the file .vscode/launch.json at the project root with this content:

.vscode/launch.json
{ "version": "0.2.0", "configurations": [ { "name": "Debug Backend", "type": "node", "request": "launch", "runtimeExecutable": "npx", "runtimeArgs": ["tsx", "src/index.ts"], "cwd": "${workspaceFolder}/backend", "envFile": "${workspaceFolder}/backend/.env", "console": "integratedTerminal", "restart": true, "skipFiles": ["<node_internals>/**", "node_modules/**"] }, { "name": "Debug Frontend (Chrome)", "type": "chrome", "request": "launch", "url": "http://localhost:5173", "webRoot": "${workspaceFolder}/frontend/src", "sourceMapPathOverrides": { "webpack:///src/*": "${webRoot}/*" } } ] }

How to Debug the Backend

  1. Open the Run and Debug panel (Ctrl+Shift+D)
  2. Select "Debug Backend" from the dropdown
  3. Click the green play button (or press F5)
  4. The backend starts in debug mode
  5. Open any backend file (e.g., backend/src/routes/api.ts)
  6. Click on the line number gutter to the left of a line — a red dot appears (breakpoint)
  7. Trigger that code path (e.g., open http://localhost:3001/api/layers/aircraft in the browser)
  8. Execution pauses at your breakpoint — you can inspect variables, step through code, etc.

18b. Debug the Frontend (React)

How to Debug the Frontend

  1. First, make sure the frontend dev server is running (npm run dev in the frontend folder)
  2. In VS Code, select "Debug Frontend (Chrome)" from the Debug dropdown
  3. Press F5 — Chrome opens with the app
  4. Back in VS Code, open any frontend file (e.g., frontend/src/App.tsx)
  5. Set breakpoints by clicking line numbers
  6. Interact with the app in Chrome — breakpoints will trigger in VS Code

18c. Alternative: Debug with console.log

The simplest way to debug (and what most developers do day-to-day):

// Add this anywhere in your code to inspect a value:
console.log('Aircraft data:', data);
console.log('Number of items:', data.length);
console.log('First item:', JSON.stringify(data[0], null, 2));
  • Backend logs appear in the terminal where npm run dev is running
  • Frontend logs appear in the browser's Developer Tools Console (F12)

! Troubleshooting

Problem: Globe is blank / black / no imagery

Cause: Missing or invalid Cesium Ion token
  1. Open frontend/.env
  2. Make sure VITE_CESIUM_ION_TOKEN= has a real token (not your_cesium_ion_token_here)
  3. Get a token from cesium.com/ion/tokens
  4. After changing the .env file, restart the frontend dev server (Ctrl+C, then npm run dev again)

Problem: npm install fails with permission errors

Fix (Windows) Run PowerShell as Administrator. Right-click PowerShell → "Run as administrator".
Fix (macOS/Linux) Do NOT use sudo npm install. Instead, fix npm permissions: npm docs guide

Problem: npm run dev says "port 3001 already in use"

Cause: Another process is using port 3001

Windows: netstat -ano | findstr :3001 then taskkill /PID <PID> /F

macOS: lsof -ti:3001 | xargs kill -9

Or change the port in backend/.env: PORT=3003

Problem: [WS] Connection error in browser console

Cause: Backend isn't running or WebSocket port blocked
  1. Make sure the backend is running (npm run dev in the backend folder)
  2. Check the backend terminal for errors
  3. The frontend expects WebSocket on ws://localhost:3002 — make sure WS_PORT=3002 in backend/.env

Problem: All layer counts show 0

Possible causes:
  1. Backend not running — start it with npm run dev in the backend folder
  2. Data hasn't loaded yet — wait 10-30 seconds for the first data fetch
  3. External APIs might be down — check backend terminal for error messages
  4. Network/firewall blocking outgoing requests

Problem: 'tsx' is not recognized as a command

Fix This means npm install didn't run correctly in the backend folder. Run: 
cd backend
npm install
Then try npm run dev again.

Problem: TypeScript compilation errors

Fix
  1. Make sure you're using Node.js v20+ (node --version)
  2. Delete node_modules and reinstall: rm -rf node_modules && npm install
  3. On Windows PowerShell: Remove-Item -Recurse -Force node_modules; npm install

Problem: ERR_OSSL_EVP_UNSUPPORTED

Fix This happens with newer Node.js versions. Set the environment variable:

Windows PowerShell: $env:NODE_OPTIONS="--openssl-legacy-provider"

macOS/Linux: export NODE_OPTIONS=--openssl-legacy-provider
